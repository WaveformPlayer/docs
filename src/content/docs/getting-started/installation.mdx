WaveformPlayer is plain, dependency-free JavaScript. Add the stylesheet and the
script, and it upgrades any `[data-waveform-player]` element on the page — no
build step required.

## CDN (no build step)

```html
<link rel="stylesheet" href="https://unpkg.com/@arraypress/waveform-player/dist/waveform-player.css">
<script src="https://unpkg.com/@arraypress/waveform-player/dist/waveform-player.min.js"></script>
```

That's everything. The script auto-initialises on load — see [Quick start](/getting-started/quick-start/).

The 2.0 bundles support **Chrome/Edge 111+, Firefox 114+ and Safari 16.4+**. Coming from 1.x? Read [Migrating from 1.x](/getting-started/migrating-from-1x/) — and note that an unversioned or `@latest` CDN URL serves 2.0.

The package is ES modules only and ships its TypeScript types. Bundling or rendering on the server needs Node 22.12+ (where `require()` of the package also works). Then import the core and the stylesheet:

```js
import { WaveformPlayer } from '@arraypress/waveform-player';
import '@arraypress/waveform-player/dist/waveform-player.css';
```

## Entry points

The package exposes two JavaScript entry points. They are the same library — same class, same options, same events — and differ in one thing: whether importing scans the page.

| Import | What loading it does |
| --- | --- |
| `@arraypress/waveform-player` | Builds a player for every `[data-waveform-player]` on the page, then hands you the class. |
| `@arraypress/waveform-player/no-autoinit` | Hands you the class. Nothing else — not even the [`<waveform-player>`](/player/element/) registration (call `defineWaveformPlayerElement()`). |

The default is what you want on a page you author: drop the markup in, import once, and the players appear.

Reach for `/no-autoinit` when your code is **bundled into a page you don't author** — a CMS block, a WordPress plugin, a widget embedded in someone else's template. There, the markup on the page isn't yours to upgrade, and you have no `<html>` in scope to mark with the [`data-waveform-autoinit` opt-out](/player/data-attributes/#initialising-only-what-you-control) before your `import` is evaluated:

```js
import WaveformPlayer from '@arraypress/waveform-player/no-autoinit';
import '@arraypress/waveform-player/dist/waveform-player.css';

// Nothing has been initialised. You decide what becomes a player:
new WaveformPlayer( myElement, { url: '/audio/track.mp3' } );
WaveformPlayer.init( myContainer );   // or scan a subtree you own
```

<Aside type="note">
In 2.0 the two ES module entries share one chunk, so a bundle that imports both (say, the bar's root import plus a framework component's `/no-autoinit`) still has one class and one instance registry. Don't load the script-tag build beside a bundled import, though: that is a second copy.
</Aside>

Full detail: [choosing an entry point](/player/data-attributes/#if-you-dont-control-the-page-either).

## Framework packages

Using React, Vue, Svelte or Astro? Install the one package for your framework
plus the cores you use, and import each component from its sub-path:

```sh
npm i @arraypress/waveform-react @arraypress/waveform-player
```

```tsx
import { WaveformPlayer } from '@arraypress/waveform-react/player';
```

| Framework | Package | Sub-paths | Requires |
| --- | --- | --- | --- |
| [React](/frameworks/react/) | `@arraypress/waveform-react` | `/player` `/bar` `/playlist` `/sounds` | React 19.3+ |
| [Vue](/frameworks/vue/) | `@arraypress/waveform-vue` | `/player` `/bar` `/playlist` `/sounds` | Vue 3.5+ |
| [Svelte](/frameworks/svelte/) | `@arraypress/waveform-svelte` | `/player` `/bar` `/playlist` `/sounds` | Svelte 5.59+ |
| [Astro](/frameworks/astro/) | `@arraypress/waveform-astro` | `/player` `/bar` `/playlist` `/sounds` | Astro 7.4+ |

The cores (`@arraypress/waveform-player`, `-bar`, `-playlist`, `-sounds`) are
optional peer dependencies, so npm installs only the ones you add. These four
packages replace the sixteen 1.x `@arraypress/waveform-<core>-<framework>`
wrappers.
