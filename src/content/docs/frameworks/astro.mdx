`@arraypress/waveform-astro` ships first-class Astro components for all four runtimes, one sub-path each. Each one turns the core library's `data-*` attribute contract into a typed `.astro` component: you pass camelCase props, the component stringifies them into the exact attributes the framework-agnostic core scans for, and the core's auto-initialiser mounts the UI on the client.

| Import from | Component(s) | Wraps |
| --- | --- | --- |
| `@arraypress/waveform-astro/player` | `<WaveformPlayer>` | [`@arraypress/waveform-player`](/player/options/) |
| `@arraypress/waveform-astro/bar` | `<WaveformBar>`, `<WaveformBarTrigger>` | `@arraypress/waveform-bar` |
| `@arraypress/waveform-astro/playlist` | `<WaveformPlaylist>` | `@arraypress/waveform-playlist` |
| `@arraypress/waveform-astro/sounds` | `<WaveformSounds>` | [`@arraypress/waveform-sounds`](/extensions/sounds/) |

:::note[Coming from 1.x]
The four 1.x wrappers are replaced by this one package. They are deprecated, and 1.x keeps working; the core package names are unchanged.

| 1.x | 2.0 |
| --- | --- |
| `@arraypress/waveform-player-astro` | `@arraypress/waveform-astro/player` |
| `@arraypress/waveform-bar-astro` | `@arraypress/waveform-astro/bar` |
| `@arraypress/waveform-playlist-astro` | `@arraypress/waveform-astro/playlist` |
| `@arraypress/waveform-sounds-astro` | `@arraypress/waveform-astro/sounds` |
| `<old>/WaveformX.astro`, `<old>/types` | `.../<name>/WaveformX.astro`, `.../<name>/types` |

`<WaveformPlayer lazy>` keeps working, but it is now the core's [`lazy`](/player/lazy-loading/) option: CSS or JS that targeted `[data-waveform-player-lazy]` must use `[data-lazy="true"]`. Astro 6 is no longer supported. See [Migrating from 1.x](/getting-started/migrating-from-1x/).
:::

The player, bar and playlist components share the same design (the sound list differs in two ways — it [server-renders the list and loads its own runtime](#the-sound-list)):

- **Props mirror core options 1:1** (camelCase). The component handles the kebab-case `data-*` conversion under the hood.
- **Omission preserves defaults.** An omitted prop emits no attribute, so the core applies its own internal default. Never pass `null` to "reset" a value — just leave the prop out.
- **The component does not load the runtime.** You load the core JS + CSS once in a layout, so you stay in control of CDN vs. self-hosted vs. bundled.
- **SSR-safe.** The server renders a plain container plus a small `is:inline` boot script; nothing in the component touches `window` or the DOM at build time.
- **View-Transitions-aware.** Each component re-runs the core's idempotent `init()` on `astro:page-load` so client-side navigations remount fresh markup.

<Aside type="note">
The prop names, defaults, and full option surface are documented on the runtime pages — see [Player options](/player/options/) and [Player events](/player/events/). This page covers only what is Astro-specific: install, the typed prop layer, events, lazy loading, SSR/View-Transitions behaviour, and loading the runtime once.
</Aside>

### Requirements

- **Astro 7.4+** (`^7.4.0`). Astro 6 is no longer supported.
- **Node 22.12+.**
- **The 2.0 cores**, which run on Chrome/Edge 111+, Firefox 114+ and Safari 16.4+.
- **ES modules only.** The package ships its TypeScript source (`src/`), with no CommonJS build; Astro compiles it for you.

## Load the runtime once (in a layout)

The components emit markup and a boot script, but the player, bar and playlist deliberately do **not** inject the core library's JS or CSS — you decide where and how it loads. Pull the assets into your root layout's `<head>` once, and every `<WaveformPlayer>` on every page is covered.

The cleanest pattern: import the CSS so Astro bundles and hashes it, and import the minified JS with the `?url` suffix so you get a hashed URL to mount via an `is:inline` script tag.

```astro title="src/layouts/Layout.astro"
---
import '@arraypress/waveform-player/dist/waveform-player.css';
import wfpJsUrl from '@arraypress/waveform-player/dist/waveform-player.min.js?url';
---
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <script src={wfpJsUrl} is:inline></script>
  </head>
  <body>
    <slot />
  </body>
</html>
```

The core's script installs `window.WaveformPlayer` and scans the page for players on `DOMContentLoaded`; the component's boot script only re-runs that scan after a [View Transitions](#astro-view-transitions) navigation. Without the script tag nothing mounts, so if your players stay empty, check that it loads.

## The player component

Import the default export and drop it anywhere. `url` (or its alias `src`) is the one prop you almost always pass; everything else is optional and falls through to the core's defaults when omitted.

```astro
---
import WaveformPlayer from '@arraypress/waveform-astro/player';
---
<WaveformPlayer
  url="/audio/track.mp3"
  title="Midnight Drive"
  artist="The Synthwaves"
  waveformStyle="mirror"
  waveformColor={['#fafafa', '#71717a']}
  showBPM
/>
```

That renders a single `<div class="wfp-host" data-waveform-player data-url="/audio/track.mp3" …>` plus an inline init script. On the client, the core's auto-initialiser finds the container and builds the player into it. (The core also has a [`<waveform-player>` custom element](/player/element/); the component renders the `data-*` container instead.)

### Prop reference

Props are inherited verbatim from the core's `WaveformPlayerOptions`, so the [full option list](/player/options/) is the source of truth. Each prop is emitted as its `data-*` attribute only when you set it. The most common props:

| Prop | Type | Attribute | Notes |
| --- | --- | --- | --- |
| `url` | `string` | `data-url` | Audio source. Alias `src` is also accepted; `url` wins if both are set. |
| `waveformStyle` | `'bars' \| 'mirror' \| 'line' \| 'blocks' \| 'dots' \| 'seekbar'` | `data-waveform-style` | Visual style. Use this, **not** `style` (see below). |
| `height` | `number` | `data-height` | Waveform height in px. |
| `samples` | `number` | `data-samples` | Source peak resolution decoded. |
| `waveform` | `number[] \| string` | `data-waveform` | Pre-computed peaks: an array, a CSV/JSON string, a `.json` URL, or compact `wp1:` peaks. Arrays are JSON-encoded for you. |
| `waveformColor` / `progressColor` | `string \| string[]` | `data-waveform-color` / `data-progress-color` | A CSS colour or an array of gradient stops (top→bottom). Arrays are JSON-encoded into the attribute automatically. |
| `colorPreset` | `'dark' \| 'light'` | `data-color-preset` | Forces a theme; omit for auto-detection. |
| `markers` | `Array<{ time: number; label: string; color?: string }>` | `data-markers` | Cue markers; JSON-encoded for you. |
| `audioMode` | `'self' \| 'external'` | `data-audio-mode` | `'self'` owns an `<audio>`; `'external'` is visualization-only. |
| `crossOrigin` | `'anonymous' \| 'use-credentials'` | `data-cross-origin` | CORS mode for the `<audio>`. Unset by default (native `<audio>` behavior); set only if you need it. |
| `showBPM`, `showControls`, `showInfo`, `showTime` | `boolean` | `data-show-bpm`, `data-show-controls`, … | UI toggles. Astro boolean shorthand works: `showBPM` ≡ `showBPM={true}`. |
| `duration` | `number` | `data-duration` | **2.0.** Track length in seconds, shown as the total (and used for markers and seeks) until the audio's metadata arrives — with `preload="none"`, until play. See [Zero-bandwidth players](/player/zero-bandwidth/). |
| `lazy` | `boolean` | `data-lazy` | **2.0 (core option).** Build the player now; load the audio and peaks, and draw, within 200px of the viewport. See [Lazy loading](#lazy-loading). |
| `loop` | `boolean` | `data-loop` | **2.0.** Loop the whole track. Self mode only. See [Looping](/player/looping/). |
| `showLoop` | `boolean` | `data-show-loop` | **2.0.** A loop toggle button in the meta row (needs `showInfo`). Self mode only. |
| `loopLabel` | `string` | `data-loop-label` | **2.0.** Accessible name of the loop button. Default `'Loop'`. |
| `showVolume` | `boolean` | `data-show-volume` | **2.0.** A mute toggle and volume slider in the meta row (needs `showInfo`). Self mode only. |
| `volume` | `number` | `data-volume` | **2.0.** Initial volume, `0`..`1` (clamped). Self mode only. |
| `volumeLabel` | `string` | `data-volume-label` | **2.0.** Accessible name of the volume slider. Default `'Volume'`. |
| `muteLabel` | `string` | `data-mute-label` | **2.0.** Accessible name of the mute toggle. Default `'Mute'`. |
| `showDownload` | `boolean` | `data-show-download` | **2.0.** A download link in the meta row (needs `showInfo`). Cross-origin URLs need `Content-Disposition: attachment`. |
| `downloadUrl` | `string` | `data-download-url` | **2.0.** Where the download link points. Default: the track's `url`. |
| `downloadName` | `string` | `data-download-name` | **2.0.** Suggested file name. Default: the url's file name. |
| `downloadLabel` | `string` | `data-download-label` | **2.0.** Accessible name of the download link. Default `'Download'`. |

### Astro-specific props

On top of the inherited options, the component adds three extras:

| Prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `id` | `string` | — | DOM id forwarded to the container; target it via `WaveformPlayer.getInstance(id)`. |
| `class` | `string` | — | Extra class names. The base class `wfp-host` is always applied. |
| `style` | `string` | — | Inline CSS on the container — handy for a `min-height` to reserve layout space before the canvas draws. |

<Aside type="caution">
**`style` is the HTML inline-style attribute, not the waveform style.** The core exposes `style` as a shorthand alias for `waveformStyle` (via `data-style`), but in an Astro component `style` is reserved for inline CSS. The component removes the alias — always select the visual style with the canonical `waveformStyle` prop.
</Aside>

### Events

There are no callback props: a server-rendered component emits static HTML with nothing to attach a JS function to, so `onLoad`, `onPlay`, `onPause`, `onEnd`, `onError`, `onTimeUpdate`, `onNextTrack` and `onPreviousTrack` are absent from the prop type. Instead, every player dispatches bubbling, composed [`waveformplayer:*` CustomEvents](/player/events/) on its container, typed on `DocumentEventMap` by the core, so one listener on `document` hears them all. `detail.player` is the instance.

| Event | `detail` (besides `player`, `url`) |
| --- | --- |
| `waveformplayer:ready` / `load` / `play` / `pause` / `destroy` | — |
| `waveformplayer:ended` | `currentTime`, `duration` |
| `waveformplayer:timeupdate` | `currentTime`, `duration`, `progress` |
| `waveformplayer:error` | `error` |
| `waveformplayer:seek` (2.0) | `currentTime`, `duration` |
| `waveformplayer:ratechange` (2.0) | `playbackRate` |
| `waveformplayer:volumechange` (2.0) | `volume`, `muted` |
| `waveformplayer:loop` (2.0) | `loop`, `start`, `end` |
| `waveformplayer:next` / `previous` | — (lock-screen skip buttons) |
| `waveformplayer:request-play` / `request-pause` / `request-seek` | for `audioMode="external"` controllers |

`seek`, `ratechange`, `volumechange` and `loop` come from the player's own `<audio>`, so they don't fire with `audioMode="external"`.

```astro
<WaveformPlayer id="hero" url="/audio/track.mp3" />

<script>
  document.getElementById('hero')?.addEventListener('waveformplayer:ended', (e) => {
    console.log('finished', e.detail.url);
  });

  document.addEventListener('waveformplayer:seek', (e) => {
    console.log('seeked to', e.detail.currentTime);
  });
</script>
```

The detail types (`WaveformSeekEventDetail`, …, `WaveformPlayerEventMap`) are exported from `@arraypress/waveform-astro/player`. For the instance's methods, see [Methods](/player/methods/).

### Pre-computed peaks (recommended for catalogues)

Decoding audio with Web Audio is expensive, especially across a grid. Ship a sibling `.json` peaks file and pass it as `waveform` to skip the decode entirely:

```astro
<WaveformPlayer
  url="/audio/track.mp3"
  waveform="/peaks/track.json"
  waveformStyle="bars"
  barWidth={3}
  showBPM
/>
```

The peaks file may embed `{ peaks, markers }`; the core applies embedded markers automatically.

`waveform` also takes compact `wp1:` peaks inline (about a quarter of the size of a JSON array; [`waveform-gen`](/extensions/gen/) writes them). With `preload="none"` and a known `duration`, the player draws and shows its length with no audio traffic until play — see [Zero-bandwidth players](/player/zero-bandwidth/):

```astro
<WaveformPlayer url="/audio/track.mp3" preload="none" duration={187} waveform="wp1:M5lm…" />
```

## Lazy loading

Mounting 15+ players on one page means 15+ concurrent `fetch()` + `decodeAudioData` jobs firing on load — janky, and prone to "Unable to load audio" stutters. Pass `lazy` to defer each player's loading until it approaches the viewport.

```astro
---
import WaveformPlayer from '@arraypress/waveform-astro/player';
const previews = await getPreviews();
---
<div class="grid">
  {previews.map((p) => (
    <WaveformPlayer url={p.url} title={p.title} waveform={p.peaks} duration={p.seconds} lazy />
  ))}
</div>
```

`lazy` is the core's own [`lazy` option](/player/lazy-loading/), emitted as `data-lazy="true"`. The player is built at once — registered, its methods working, its title, loading state and any known `duration` shown at full height, so nothing shifts — and the core defers assigning the audio, fetching the peaks and drawing until it is within 200px of the viewport, with one `IntersectionObserver` shared by every lazy player. Playing or seeking loads it straight away.

<Aside type="caution">
**Changed in 2.0.** In 1.x, `lazy` was the component's own: it rendered `data-waveform-player-lazy` and shipped an inline observer that built the player only as it neared the viewport. That script is gone. `<WaveformPlayer lazy>` keeps working unchanged; only CSS or JS that targeted `[data-waveform-player-lazy]` must use `[data-lazy="true"]` instead.
</Aside>

<Aside type="tip">
Reach for `lazy` on long lists and grids of previews. For a single hero player above the fold there is no benefit.
</Aside>

## SSR safety

The component is pure markup generation. At build / request time it:

- reads `Astro.props`, builds a `Record<string, string>` of `data-*` attributes, and renders one `<div>`;
- emits `is:inline` boot scripts (the View Transitions re-init and teardown).

It never references `window`, `document`, `IntersectionObserver`, or the `AudioContext` during render — those names appear only inside the inline scripts, which run on the client. That makes the component safe in any Astro output mode (`static`, `server`, `hybrid`) and inside `.astro` files rendered on the edge.

## Astro View Transitions

The core auto-initialises on `DOMContentLoaded` only. Under [View Transitions](https://docs.astro.build/en/guides/view-transitions/), client-side navigations swap the DOM without re-firing that event, so a freshly-rendered player would never mount after a navigation.

Every `<WaveformPlayer>` (lazy ones included) ships a tiny boot script that re-runs the core's idempotent `WaveformPlayer.init()` on each `astro:page-load`. It deduplicates via `window.__wfpInitBound` (one shared listener), and the core skips any container already flagged `data-waveform-initialized`, so re-running it only mounts the new ones. On `astro:before-swap` it also destroys the players whose containers are leaving the page, so their audio stops, keeping any inside a `transition:persist` host the next page carries over. No configuration required — it just works once you enable View Transitions in your layout.

## The bar

`@arraypress/waveform-astro/bar` exposes two components:

- **`<WaveformBar>`** — the persistent bottom-bar singleton. Render it **once** in your root layout.
- **`<WaveformBarTrigger>`** — a polymorphic play/queue trigger you scatter across cards, rows, and modals.

### Setup — load both runtimes

The bar depends on the core player, so load **both** scripts (player first, bar second) and both stylesheets:

```astro title="src/layouts/Layout.astro"
---
import '@arraypress/waveform-player/dist/waveform-player.css';
import '@arraypress/waveform-bar/dist/waveform-bar.css';
import wfpJsUrl from '@arraypress/waveform-player/dist/waveform-player.min.js?url';
import wbJsUrl  from '@arraypress/waveform-bar/dist/waveform-bar.min.js?url';
import { WaveformBar } from '@arraypress/waveform-astro/bar';
---
<html lang="en">
  <head>
    <script src={wfpJsUrl} is:inline></script>
    <script src={wbJsUrl}  is:inline></script>
  </head>
  <body>
    <slot />
    <WaveformBar config={{ persist: true, continuous: true, showQueue: true }} />
  </body>
</html>
```

### `<WaveformBar>` — the singleton mount

| Prop | Type | Default | Purpose |
| --- | --- | --- | --- |
| `config` | `WaveformBarConfig` | `{}` | Passed verbatim to `window.WaveformBar.init(config)`. Omit for all defaults. |
| `persist` | `boolean` | `true` | Render the host with `transition:persist` so the bar survives View Transitions intact. |
| `hostId` | `string` | `'waveform-bar-host'` | DOM id of the persistent host `<div>`. |
| `class` | `string` | — | Extra class names on the host (base class `wb-host`). |

The component renders one persistent host `<div>` and an inline script that calls `WaveformBar.init(config)` **exactly once** per session (guarded by `window.__wbAstroInitBound` and `window.__apWaveformBarInited`). This once-only behaviour is deliberate: the core's `init()` destroys and rebuilds the bar on each call, which would restart the playing audio and defeat `transition:persist`. After init, the script relocates the library's `.waveform-bar` element into the persist host so navigations keep it on screen.

<Aside type="caution">
Render `<WaveformBar>` **exactly once**, in your root layout, after your main content. There is only one bar per page; a second instance would call `init()` again and the last one wins.
</Aside>

A representative slice of `WaveformBarConfig` (every field optional):

| Field | Type | Default | |
| --- | --- | --- | --- |
| `persist` | `boolean` | `true` | Save queue/position to storage; resume across loads. |
| `autoResume` | `boolean` | `true` | Resume playback after a navigation. |
| `continuous` | `boolean` | `true` | Auto-advance to the next queued track. |
| `repeat` | `'off' \| 'all' \| 'one'` | `'off'` | Initial repeat mode. |
| `showQueue` | `boolean` | `true` | Show the queue toggle + panel. |
| `waveformStyle` | `WaveformStyle` | `'mirror'` | Waveform style inside the bar. |
| `maxMeta` | `number` | `3` | Cap on metadata chips (BPM/key/tags). |
| `theme` | `'dark' \| 'light' \| null` | `null` | Forced theme; `null` auto-detects. |
| `position` | `'bottom' \| 'top'` | `'bottom'` | Which edge the bar docks to. |
| `mode` | `'waveform' \| 'classic'` | `'waveform'` | `'classic'` = Spotify-style centre layout + seek bar. |
| `share` | `boolean` | `false` | Show a "copy share link" button with a timestamp param. |
| `actions` | `{ favorite?, cart? }` | — | Favourite / cart endpoint config (see caveat). |

<Aside type="caution">
**Function-valued config can't cross the SSR boundary.** Astro serialises `config` as JSON, so anything non-JSON (functions, Dates, RegExps) is dropped. In particular `actions.favorite.endpoint` accepts a function in the core, but from Astro you can only pass a URL string. Need the function form? Skip the `<WaveformBar>` component for that field and call `window.WaveformBar.init({ actions: { favorite: { endpoint: fn } } })` from your own client script.
</Aside>

### `<WaveformBarTrigger>` — play / queue triggers

A polymorphic element that emits the `data-wb-*` attribute contract the bar's runtime click-delegation scans for. It defaults to a `<button>` (keyboard focus, Space/Enter, accessible role for free) and injects a play/pause SVG pair the bar toggles per track. Pass children to replace those defaults.

```astro
---
import { WaveformBarTrigger } from '@arraypress/waveform-astro/bar';
const { product } = Astro.props;
---
<article class="product-card">
  <img src={product.cover} alt="" />
  <h3>{product.title}</h3>

  <WaveformBarTrigger
    url={product.previewUrl}
    id={product.id}
    title={product.title}
    artist={product.artist}
    artwork={product.cover}
    waveform={product.peaks}
    class="card-play-btn"
  />

  <WaveformBarTrigger mode="queue" url={product.previewUrl} title={product.title}>
    + Queue
  </WaveformBarTrigger>
</article>
```

Key props (every track field optional except `url`):

| Prop | Type | Default | Becomes |
| --- | --- | --- | --- |
| `mode` | `'play' \| 'queue'` | `'play'` | `data-wb-play` / `data-wb-queue` |
| `as` | `'button' \| 'a' \| 'div' \| 'span'` | `'button'` | the rendered tag |
| `url` | `string` | — | `data-wb-url` (the play target / identity) |
| `id` | `string` | falls back to `url` | `data-wb-id` |
| `title`, `artist`, `album`, `artwork`, `link` | `string` | — | `data-wb-title`, `-artist`, `-album`, `-artwork`, `-link` |
| `duration` | `string \| number` | — | `data-wb-duration` — seconds (`187`) or a clock string (`'3:07'`); the bar shows it and passes it to the player |
| `bpm` | `string \| number` | — | `data-wb-bpm` |
| `key` | `string` | — | `data-wb-key` |
| `meta` | `string[]` | — | `data-wb-meta` (JSON) |
| `waveform` | `number[] \| string` | — | `data-wb-waveform` — an array (JSON-encoded), a `.json` URL, a CSV string, or compact `wp1:` peaks |
| `markers` | `WaveformBarMarker[]` | — | `data-wb-markers` (JSON) — DJ-mode chapter markers |
| `favorited`, `inCart` | `boolean` | — | `data-wb-favorited`, `-in-cart` |
| `href` | `string` | — | rendered only when `as="a"` |
| `ariaLabel` | `string` | auto from `title` | accessible name |
| `noDefaultIcons` | `boolean` | `false` | suppress the injected play/pause SVGs |

<Aside type="note">
The bar dispatches every state change as a bubbling `waveformbar:*` `CustomEvent`. Listen to those from a client script for play/pause/favourite/cart side-effects — that is the framework-agnostic path, and it is why triggers expose no callback props.
</Aside>

## The playlist

`@arraypress/waveform-astro/playlist` wraps the playlist runtime, which embeds a self-mode player and renders one row per track with optional chapters. The component turns the nested `[data-track]` / `[data-chapter]` markup into a single typed `tracks` array.

### Setup — load both runtimes

Load the player and playlist scripts (player first) and both stylesheets:

```astro title="src/layouts/Layout.astro"
---
import '@arraypress/waveform-player/dist/waveform-player.css';
import '@arraypress/waveform-playlist/dist/waveform-playlist.css';
import wfpJsUrl  from '@arraypress/waveform-player/dist/waveform-player.min.js?url';
import wfplJsUrl from '@arraypress/waveform-playlist/dist/waveform-playlist.js?url';
---
<head>
  <script src={wfpJsUrl}  is:inline></script>
  <script src={wfplJsUrl} is:inline></script>
</head>
```

### Example — podcast with chapters

```astro
---
import WaveformPlaylist from '@arraypress/waveform-astro/playlist';
---
<WaveformPlaylist
  continuous
  showPlayState
  tracks={[
    {
      url: '/audio/ep42.mp3',
      title: 'Episode 42',
      artist: 'with Dr. Sarah Chen',
      artwork: '/img/ep42.jpg',
      duration: '48:12',
      chapters: [
        { time: 0, label: 'Intro' },
        { time: 330, label: 'Main Topic' },
        { time: 2700, label: 'Q&A' },
      ],
    },
  ]}
/>
```

This renders a `[data-waveform-playlist]` container with one `[data-track]` child per entry and one `[data-chapter]` child per chapter.

### Playlist-specific props

| Prop | Type | Purpose |
| --- | --- | --- |
| `tracks` | `WaveformPlaylistTrackInput[]` | **Required.** One entry per track. |
| `layout` | `'list' \| 'minimal' \| 'hero' \| 'grid'` | Playlist layout. |
| `showArtist`, `coverSize`, `thumbnailSize`, `density`, `coverPosition`, `barPosition` | — | Layout options for the hero / grid layouts and row density. See [Playlist options](/extensions/playlist/options/). |
| `continuous` | `boolean` | Auto-advance to the next track. |
| `expandChapters` | `boolean` | Expand the chapter list by default. |
| `showDuration` | `boolean` | Show per-track durations. |
| `showChapterMarkers` | `boolean \| null` | Render chapter markers on the waveform; `null` (default) uses the content-aware smart default. |
| `chapterMarkerColor` | `string` | Chapter marker line colour. |
| `showPlayState` | `boolean` | Show the playing/paused state per row. |
| `lazy` | `boolean` | Defer building the whole playlist until it nears the viewport (see below). Not the player's `lazy`. |

Each `WaveformPlaylistTrackInput` accepts:

| Field | Type | Becomes |
| --- | --- | --- |
| `url` | `string` | `data-url` |
| `title`, `artist`, `artwork`, `album` | `string` | `data-title`, `-artist`, `-artwork`, `-album` |
| `duration` | `number \| string` | `data-duration` — seconds (`225`) or a clock string (`'3:45'`). The playlist shows it and, from 2.0, passes it to the player as its `duration`. |
| `downloadUrl` | `string` | `data-download-url` — this track's download link (with `showDownload` on the playlist). Default: the track's `url`. |
| `downloadName` | `string` | `data-download-name` — suggested file name. Default: the url's file name. |
| `waveform` | `number[] \| string` | `data-waveform` — an array (JSON-encoded), a `.json` URL, or compact `wp1:` peaks |
| `markers` | `{ time: number; label?: string; color?: string }[]` | `data-markers` (JSON) — waveform cue markers |
| `chapters` | `{ time: number; label: string; color?: string }[]` | nested `[data-chapter]` rows |

The component also forwards the embedded player's options (`waveformStyle`, `height`, `samples`, `barWidth`, the colour props, `showBPM`, `accessibleSeek`, …) straight onto the container, where the playlist reads and passes them to the player it builds. That includes 2.0's `showVolume`, `volume`, `volumeLabel`, `muteLabel`, `showDownload` and `downloadLabel` (each track's download target is its own `downloadUrl` / `downloadName`).

<Aside type="caution">
Some player options are **not** container props:

- **Per-track content** (`url`, `src`, `title`, `artist`, `artwork`, `album`, `markers`, `waveform`, and 2.0's `duration`, `downloadUrl`, `downloadName`) lives on each `tracks` entry; the playlist strips any container copy.
- **What the playlist never passes to its player:** `audioMode` (it always drives a self-mode player), `loop` (a looping track never ends, which breaks `continuous`), `showLoop`, `loopLabel`, and the player's `lazy` (the playlist loads its player itself).
- **The player's `layout`** (`'default' | 'preview'`) collides with the playlist's `layout` on the same `data-layout` attribute; the playlist's wins.
- **Callbacks**, including `onNextTrack` / `onPreviousTrack` — listen for the [events](#events) instead.
</Aside>

The playlist's own `lazy` is unchanged from 1.x: it emits `data-waveform-playlist-lazy`, and an inline observer (deduped via `window.__wfplLazyMountBound`, 200px of buffer) promotes it to `data-waveform-playlist` and builds the playlist as it nears the viewport. If `window.WaveformPlaylist` hasn't loaded, it retries for ~1s and then logs a one-time `[WaveformPlaylistAstro]` warning. A non-lazy playlist ships the View Transitions re-init instead (deduped via `window.__wfplInitBound`).

## The sound list

`@arraypress/waveform-astro/sounds` wraps [WaveformSounds](/extensions/sounds/), the searchable, filterable list of sound previews. It breaks from the other three components in two ways:

- **It renders the whole list on the server.** Given `sounds`, the component writes the toolbar, the chips and every row with the core's DOM-free renderer (`@arraypress/waveform-sounds/render`); the browser runtime adopts that markup instead of rebuilding it, so the list is readable and crawlable before any script runs.
- **It loads its own JavaScript.** The component ships one processed (bundled) `<script>` that loads the sounds runtime, and the player too unless the page already has one. You only add the stylesheets.

### Setup

```sh
npm install @arraypress/waveform-astro @arraypress/waveform-sounds @arraypress/waveform-player
```

Import the two stylesheets once, in your layout — the component doesn't inject CSS:

```astro title="src/layouts/Layout.astro"
---
import '@arraypress/waveform-player/styles.css';
import '@arraypress/waveform-sounds/styles.css';
---
```

### Example — from an array, server-rendered

```astro
---
import WaveformSounds from '@arraypress/waveform-astro/sounds';
---
<WaveformSounds
  sounds={[
    { url: '/previews/kick-01.mp3', title: 'Kick 01', type: 'Drums', bpm: 128, key: 'F minor', duration: 2.4 },
    { url: '/previews/bass-04.mp3', title: 'Bass Loop 04', type: 'Bass', bpm: 128, key: 'Fmin', peaks: 'a1b2c3…' },
  ]}
  pageSize={100}
  columns={['type', 'bpm', 'key']}
/>
```

### Example — from a manifest

```astro
<WaveformSounds manifest="/previews/sounds.json" player="strip" />
```

With only `manifest` (and no `sounds`), the component renders an empty container carrying `data-manifest`, and the runtime fetches and renders the list in the browser. To server-render a manifest instead, read it at build time and pass its `sounds` array:

```astro
---
import WaveformSounds from '@arraypress/waveform-astro/sounds';
import pack from '../../public/previews/sounds.json';
---
<WaveformSounds sounds={pack.sounds} />
```

Write the manifest with [`waveform-gen --manifest`](/extensions/gen/manifest/) — and set its `--base-url` to where the audio is served (`/previews/` above), or the URLs point at the site root.

### Props

Every core option is a prop, typed from the core's `WaveformSoundsOptions`, and emitted as the `data-*` attribute the core reads — an omitted prop emits nothing, so the core's default applies. See [Options](/extensions/sounds/options/) for each one.

| Prop | Type | Notes |
| --- | --- | --- |
| `sounds` | `SoundInput[]` | Rendered on the server. An empty array renders an empty list (the manifest isn't fetched). |
| `manifest` | `string` | Fetched in the browser when there are no `sounds`. |
| `player` | `'inline' \| 'strip'` | Always emitted (resolved the way the core resolves it). |
| `search`, `showCount`, `loopToggle`, `loop`, `autoAdvance`, `arrowAudition` | `boolean` | Emitted as `"true"` / `"false"`. |
| `filters`, `sorts`, `columns` | `string[]` | Comma-separated; an empty array is emitted as `""` = none. |
| `menuSearch`, `pageSize`, `maxTypeChips`, `barWidth`, `barGap` | `number` | |
| `waveformStyle`, `waveformColor`, `progressColor` | `string` | |
| `idPrefix` | `string` | Defaults to `id`, matching the core's own client render. |
| `urlState` | `boolean \| string` | `"true"` / `"false"`, or the prefix. |
| `strings`, `playerOptions` | `object` | Emitted as JSON (functions inside `playerOptions` don't survive). |
| `id` | `string` | Container id — for `WaveformSounds.getInstance('#id')`. |
| `class` | `string` | Added to `waveform-sounds waveform-sounds--<player>`. |

Not available: the `on*` callbacks (a function can't cross into server-rendered HTML — listen for the bubbling [`waveformsounds:*` events](/extensions/sounds/api/#events) instead) and `playerClass` (the page's `window.WaveformPlayer` is used, see below).

```astro
<WaveformSounds id="pack" manifest="/previews/sounds.json" />

<script>
  document.addEventListener('waveformsounds:play', (e) => {
    console.log('playing', e.detail.sound.title);
  });
</script>
```

For the imperative API, `window.WaveformSounds.getInstance('#pack')` returns the instance. The client script creates it, so call it from an event handler or after `waveformsounds:ready`.

Set `--ws-surface` to your page background — the runtime detects it, but a server-rendered list paints before any script runs:

```css
.waveform-sounds { --ws-surface: var(--color-bg); }
```

### The client script

- **CSP-friendly.** It's a processed Astro `<script>` — one bundled module emitted as an external file, identical on every page, with no `is:inline` and no `define:vars`. Everything per-instance travels in `data-*`, so a strict hash-based Content-Security-Policy needs no extra hashes for it.
- **View Transitions.** It initialises on load and on every `astro:page-load`, and on `astro:after-swap` destroys the instances whose element left the page (stopping their audio). A list inside a `transition:persist` element is carried over and keeps playing. It works with and without `<ClientRouter />`.
- **It never replaces the page's player.** `singlePlay` only works between players of the same class, so the script waits for the page's own scripts (`DOMContentLoaded`) and uses an existing `window.WaveformPlayer` — a persistent [WaveformBar](#the-bar)'s, or one from a `<script>` tag. Only when there is none does it load the bundled `@arraypress/waveform-player` (a separate chunk, by dynamic import). A player your code loads *later* than that, from its own dynamic import, can't be detected — load it from a static `<script>` or import instead.

## TypeScript

Each sub-path re-exports the shared core types so you can import them from one place. The player, playlist and sound-list props are derived from the cores' option types via `Omit<>` / `Pick<>`, so a renamed or retyped core option flows through without an edit; the bar's types are hand-written (JSON-serialisable config, no callbacks) and kept in step with the bar's defaults by a test.

```ts
import type {
  WaveformPlayerProps,
  WaveformStyle,
  WaveformMarker,
  WaveformPeaks,
  ColorPreset,
  WaveformPlayerEventMap,
  WaveformSeekEventDetail,
} from '@arraypress/waveform-astro/player';

import type {
  WaveformBarProps,
  WaveformBarConfig,
  WaveformBarTriggerProps,
  WaveformBarTrackData,
  WaveformBarMarker,
} from '@arraypress/waveform-astro/bar';

import type {
  WaveformPlaylistProps,
  WaveformPlaylistTrackInput,
} from '@arraypress/waveform-astro/playlist';

import type {
  WaveformSoundsProps,
  SoundInput,
  SoundsManifest,
  WaveformSoundsEventMap,
} from '@arraypress/waveform-astro/sounds';
```

`window.WaveformPlayer`, `window.WaveformBar` and the `waveformplayer:*` events on `DocumentEventMap` are typed by the cores' own declarations, so `document.addEventListener('waveformplayer:seek', (e) => e.detail.currentTime)` type-checks without an import.

## Gotchas

- **Load the runtime yourself** (player, bar, playlist). Those components emit markup + a boot script but never inject the core JS/CSS. (`<WaveformSounds>` loads its own JS; every component leaves the CSS to you.) A missing player script fails quietly (nothing mounts); the bar and a lazy playlist log a one-time `[WaveformBarAstro]` / `[WaveformPlaylistAstro]` console warning.
- **Install the cores you use.** They are optional peers, so npm won't add them for you.
- **Script order matters** for the bar and playlist: load `@arraypress/waveform-player` **before** the bar/playlist script, since both depend on the core player's global.
- **`style` ≠ waveform style.** In `.astro`, `style` is inline CSS — pick the visual style with `waveformStyle`.
- **No callback props.** Wire `onLoad`/`onPlay`/etc. via the DOM `waveformplayer:*` / `waveformbar:*` events from a client script.
- **`lazy` targets `[data-lazy="true"]`** in 2.0, not `[data-waveform-player-lazy]`.
- **Render `<WaveformBar>` once.** It is a singleton; a second instance re-inits the bar and restarts audio.
- **Omit, don't null.** An omitted prop emits no attribute and lets the core default win; passing `null` is not a reset.
