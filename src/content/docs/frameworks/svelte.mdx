`@arraypress/waveform-svelte` is one package of Svelte 5 components, each a thin, typed wrapper over its vanilla core — built with runes (`$props`, `$effect`, `$derived`). Every component lives at its own sub-path and loads its core on mount. The cores are **optional** peer dependencies, so install only the ones for the sub-paths you import:

| Import | Component(s) | Install alongside `svelte` |
| --- | --- | --- |
| `@arraypress/waveform-svelte/player` | `<WaveformPlayer>` | [`@arraypress/waveform-player`](/player/options/) |
| `@arraypress/waveform-svelte/bar` | `<WaveformBar>`, `<WaveformBarTrigger>` | [`@arraypress/waveform-bar`](/extensions/bar/) + `@arraypress/waveform-player` |
| `@arraypress/waveform-svelte/playlist` | `<WaveformPlaylist>` | [`@arraypress/waveform-playlist`](/extensions/playlist/) + `@arraypress/waveform-player` |
| `@arraypress/waveform-svelte/sounds` | `<WaveformSounds>` | [`@arraypress/waveform-sounds`](/extensions/sounds/) + `@arraypress/waveform-player` |

There is no root import: `import … from '@arraypress/waveform-svelte'` is an error on purpose, because a combined entry would make your bundler resolve every core, including the ones you didn't install.

**Requirements:** Svelte **5.59+** (peer `^5.59.0`), every core **2.0+** (`^2.0.0`; `-playlist` `^2.1.0`, `-sounds` `^2.2.0`), Node **22.12+**, ES modules only. Browsers: Chrome/Edge 111+, Firefox 114+, Safari 16.4+. Types ship with the package.

:::note[Coming from 1.x]
The four separate wrappers are replaced by this one package and are deprecated — they keep working with the 1.x cores, but get no 2.0 features. Each sub-path exports what its old package did, with the same props, callbacks and instance methods, plus the 2.0 additions below. Change the import and move the cores to 2.0:

| Before | After |
| --- | --- |
| `@arraypress/waveform-player-svelte` | `@arraypress/waveform-svelte/player` |
| `@arraypress/waveform-bar-svelte` | `@arraypress/waveform-svelte/bar` |
| `@arraypress/waveform-playlist-svelte` | `@arraypress/waveform-svelte/playlist` |
| `@arraypress/waveform-sounds-svelte` | `@arraypress/waveform-svelte/sounds` |

See [Migrating from 1.x](/getting-started/migrating-from-1x/) for the core changes.
:::

Every component follows the same design:

- **Prop types are derived from the core's own typings** (`WaveformPlayerOptions`; `WaveformPlaylistOptions`; `WaveformSoundsOptions` for the sound list), not re-declared — so they never drift as the core evolves. (The bar's `WaveformBarConfig` is still declared by the wrapper; see [below](#waveformbarconfig).)
- **The core JS is dynamically `import()`ed inside `$effect`**, which only runs in the browser — so the audio + canvas + `fetch` surface never runs during SSR / SvelteKit prerendering.
- **The imperative API is exposed as Svelte 5 `export function`s**, reached through `bind:this` — `loadTrack`, `seekTo`, playlist navigation, and the rest.
- **CSS is never auto-loaded** — you import each core's stylesheet once at your app entry (e.g. the SvelteKit root `+layout.svelte`).

:::caution[Use `waveformStyle`, not `style`]
On all four components, `style` is the standard element attribute applied to the host `<div>` (a CSS string — e.g. for reserving layout height). The core's `style` alias for the *visual* waveform style is not used by the wrappers. To pick a visual style use **`waveformStyle`** (`'bars' | 'mirror' | 'line' | 'blocks' | 'dots' | 'seekbar'`). Likewise `class`, `id`, and any other element attribute fall through to the host — the base class is always applied.
:::

### Quick start

```svelte
<script lang="ts">
  import { WaveformPlayer } from '@arraypress/waveform-svelte/player';
</script>

<WaveformPlayer
  url="/audio/track.mp3"
  title="My Track"
  waveformStyle="mirror"
  waveformColor={['#fafafa', '#71717a']}
  showBPM
  ontimeupdate={(currentTime, duration) => {
    /* live progress */
  }}
/>
```

:::tip[Prefer plain markup?]
The 2.0 core also ships a [`<waveform-player>` custom element](/player/element/), which works in Svelte markup as-is. Use the component when you want typed props, callback props and `bind:this`.
:::

### Props

`WaveformPlayerProps` is `Omit<WaveformPlayerOptions, …callbacks>`, so **every player option is accepted as a typed prop** — `height`, `samples`, `barRadius`, `colorPreset`, `accessibleSeek`, `markers`, gradient-array colours, and so on. See [Player → Options](/player/options/) for the full inherited surface. Absent props are not forwarded, so the core's own defaults apply.

`src` is a shorthand alias for `url` (provide one; `url` wins if both are set). `class`, `style`, `id`, and any other element attribute fall through to the host `<div>` via `HTMLAttributes<HTMLDivElement>` — the base class `wfp-host` is always applied.

| Prop | Type | Notes |
| --- | --- | --- |
| `url` | `string` | Audio file URL. |
| `src` | `string` | Shorthand alias for `url`. |
| `waveform` | `number[] \| string` | Pre-computed peaks: an array, a `.json` URL, a JSON string, or [compact `wp1:` peaks](/player/waveform-data/#compact-peaks-wp1) (2.0). |
| `class` | `string` | Appended to the always-present base class `wfp-host`. |
| `style` | `string` | Inline CSS on the host — e.g. `min-height` to reserve space before draw. |
| `id` | `string` | Forwarded to the host `<div>`. |

#### New in 2.0

The 2.0 core options are props like any other, each forwarded only when set:

| Prop | Type | Notes |
| --- | --- | --- |
| `duration` | `number` | Track length in seconds, shown before the audio loads — so a `preload="none"` player shows its length with no audio request. See [Zero-bandwidth players](/player/zero-bandwidth/). |
| `lazy` | `boolean` | Defer loading the audio, peaks and drawing until the player nears the viewport. See [Lazy loading](/player/lazy-loading/). |
| `loop` | `boolean` | Loop the whole track (self mode). See [Looping](/player/looping/). |
| `showLoop` | `boolean` | Show a loop toggle button in the meta row (needs `showInfo`; self mode). |
| `loopLabel` | `string` | Accessible name of the loop button. |
| `showVolume` | `boolean` | Show a mute toggle and volume slider in the meta row (needs `showInfo`; self mode). |
| `volume` | `number` | Initial volume, `0..1` (self mode). |
| `volumeLabel` | `string` | Accessible name of the volume slider. |
| `muteLabel` | `string` | Accessible name of the mute toggle. |
| `showDownload` | `boolean` | Show a download link in the meta row (needs `showInfo`; both audio modes). |
| `downloadUrl` | `string` | Where the link points (default: the track's `url`). |
| `downloadName` | `string` | Suggested file name (default: the url's file name). |
| `downloadLabel` | `string` | Accessible name of the download link. |

`duration`, `downloadUrl` and `downloadName` describe the track at `url`: a `url` change remounts the player with the new values, and without the old ones.

```svelte
<!-- Shows 3:07 and the waveform without fetching any audio until play -->
<WaveformPlayer
  url="/audio/track.mp3"
  preload="none"
  duration={187}
  waveform={peaks}
  lazy
  showVolume
  showDownload
/>
```

### Callback props

Every lifecycle callback the core exposes is a lowercase callback prop (matching Svelte's native `onclick` / `oninput` convention). On this component they **replace** the host `<div>`'s same-named DOM handler types (`onplay`, `onload`, `onerror`, `onratechange`, …), so a handler's parameter is the player or the event detail, not a DOM `Event`.

```svelte
<WaveformPlayer
  url="/audio/track.mp3"
  onload={(i) => console.log('loaded', i)}
  onplay={() => console.log('playing')}
  onpause={() => console.log('paused')}
  ontimeupdate={(currentTime, duration) => console.log(`${currentTime}s / ${duration}s`)}
  onend={() => console.log('finished')}
  onerror={(err) => console.error('audio failed:', err)}
  onseek={({ currentTime }) => console.log('seeked to', currentTime)}
/>
```

| Prop | Signature | Notes |
| --- | --- | --- |
| `onload` | `(instance) => void` | Fired once after the waveform is drawn. |
| `onplay` | `(instance) => void` | Playback started (both audio modes). |
| `onpause` | `(instance) => void` | Playback paused (both modes). |
| `onend` | `(instance) => void` | Track ended (external mode synthesizes it at progress ≥ 1). |
| `ontimeupdate` | `(currentTime, duration, instance) => void` | Progress tick. Same argument order in both modes. |
| `onerror` | `(error, instance) => void` | Load / decode / audio error. |
| `onnexttrack` | `(instance) => void` | Media Session "next track". Supplying it shows the lock-screen skip button; self mode with `enableMediaSession`. |
| `onprevioustrack` | `(instance) => void` | Media Session "previous track" — the skip-back counterpart. |

**New in 2.0** — four props for the core's [`waveformplayer:*` events](/player/events/) that have no option callback. Each receives the event's `detail` (which also carries `player` and `url`), and fires in **self mode only**:

| Prop | Detail type | Detail fields |
| --- | --- | --- |
| `onseek` | `WaveformSeekEventDetail` | `currentTime`, `duration` — a click, key, marker, `seekTo()`, or a `loop` wrapping back to 0. |
| `onratechange` | `WaveformRateChangeEventDetail` | `playbackRate`. |
| `onvolumechange` | `WaveformVolumeChangeEventDetail` | `volume`, `muted`. |
| `onloop` | `WaveformLoopEventDetail` | `loop` (whole track), `start` / `end` of the section loop (or `null`). |

The detail types are re-exported from `@arraypress/waveform-svelte/player`.

:::tip[Callbacks don't trigger re-mounts]
The lowercase callback props are reactive — the wrapper reads the latest handler through a closure on each call. Passing a fresh inline function never tears the player down; only construction-time props (`url`, `audioMode`, visualization options, …) cause a re-mount. The exception is `onnexttrack` / `onprevioustrack`: adding or removing one remounts (it shows or hides the lock-screen button), but swapping one for a fresh function doesn't.
:::

:::note[Re-mount semantics]
A single `$effect` synchronously reads every construction prop, so when any of them changes the wrapper destroys the instance and constructs a new one rather than diffing options. Same-`url` re-mounts are cheap because the core caches decoded peaks keyed by URL. Wrap the component in `{#key url}` to force a clean remount, or use the imperative `loadTrack()` below to swap tracks without one.
:::

### Imperative control via `bind:this`

The component exports its API as Svelte 5 `export function`s. Grab the instance with `bind:this` and call them directly:

```svelte
<script lang="ts">
  import { WaveformPlayer } from '@arraypress/waveform-svelte/player';
  let player: WaveformPlayer;
</script>

<WaveformPlayer bind:this={player} url="/audio/track.mp3" />
<button onclick={() => player.togglePlay()}>Play / Pause</button>
<button onclick={() => player.seekTo(60)}>Jump to 1:00</button>
<button onclick={() => player.loadTrack('/audio/next.mp3', 'Next Track', 'Artist')}>
  Load next
</button>
```

| Method | Signature | Notes |
| --- | --- | --- |
| `play` | `() => Promise<void> \| undefined` | Returns the native `play()` promise in self mode; `undefined` in external mode. |
| `pause` | `() => void` | |
| `togglePlay` | `() => void` | |
| `seekTo` | `(seconds: number) => void` | Self mode only. |
| `seekToPercent` | `(percent: number) => void` | Fraction `0..1`. Self mode only. |
| `setVolume` | `(volume: number) => void` | `0..1`. Self mode only. |
| `setPlaybackRate` | `(rate: number) => void` | `0.25..4`. Self mode only. |
| `setPlayingState` | `(playing: boolean) => void` | **External mode** — push play/pause visual state. |
| `setProgress` | `(currentTime, duration) => void` | **External mode** — push the progress overlay from your own clock. |
| `loadTrack` | `(url, title?, artist?, options?) => Promise<void>` | Swap track at runtime; auto-plays unless `options.autoplay === false`. |
| `getInstance` | `() => WaveformPlayer \| null` | Escape hatch — the full core API (`load`, `setWaveformData`, `refreshTheme`, `container`, statics, …), including the 2.0 `setMuted`, `toggleLoop`, `setLoop`, `clearLoop` and `loopMarker`. |

Calls before the async import resolves are safe no-ops. The typed handle interface is exported as `WaveformPlayerExpose` for explicit typing.

:::tip[DOM events]
Prefer the callback props. For the other raw `waveformplayer:*` [events](/player/events/) (e.g. `waveformplayer:request-seek` in external mode), reach the container through the instance: `player.getInstance()?.container.addEventListener(...)`.
:::

### External audio mode

When pairing with `@arraypress/waveform-bar` (or any audio controller you own), the player can render visualization only and surrender playback. Drive it via `setProgress()` / `setPlayingState()`:

```svelte
<WaveformPlayer
  url={track.url}
  audioMode="external"
  waveformStyle="seekbar"
  showInfo={false}
  height={32}
/>
```

### Mount the bar

Render exactly **once** in your root layout. On mount the component renders a persist host, dynamically imports the core, and calls `init(config)` on the bar singleton the module exports; on unmount it calls `destroy()` so route changes don't leak listeners.

```svelte title="src/routes/+layout.svelte"
<script lang="ts">
  import { WaveformBar } from '@arraypress/waveform-svelte/bar';

  let { children } = $props();
</script>

{@render children()}

<WaveformBar
  config={{
    persist: true,
    continuous: true,
    showQueue: true,
    actions: {
      favorite: { endpoint: '/api/favorites' },
      cart: { endpoint: '/api/cart' },
    },
  }}
/>
```

| `<WaveformBar>` prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `config` | `WaveformBarConfig` | `undefined` | Passed verbatim to `init()`. See table below. |
| `persist` | `boolean` | `true` | Relocate the `.waveform-bar` element under the host `<div>` so it survives route changes. |
| `hostId` | `string` | `'waveform-bar-host'` | DOM `id` of the persist host. |

`class` and any other attribute fall through to the host `<div>` (base class `wb-host`).

:::note[Config change detection]
`init()` re-runs only when the config's structural shape changes — compared via a `$derived` `JSON.stringify` key. Passing a fresh object with the same shape on every render is safe. Function endpoints (`actions.*.endpoint`) collapse to a sentinel in that key, so pass **stable references** for those to avoid re-init churn.
:::

#### `WaveformBarConfig`

The wrapper declares this type itself (it leaves out the core's callback options — see [No callback props](#trigger-a-track) below), so this is the typed config surface. Every field is optional; see [Bar → Configuration](/extensions/bar/configuration/) for each.

| Group | Fields |
| --- | --- |
| Behaviour | `persist`, `autoResume`, `continuous`, `repeat` (`'off' \| 'all' \| 'one'`) |
| UI toggles | `showQueue`, `showPrevNext`, `showRepeat`, `showVolume`, `showMute`, `showTime`, `showTrackLink`, `showMeta`, `maxMeta` (number) |
| Layout | `wide`, `position` (`'bottom' \| 'top'`), `collapsible`, `mode` (`'waveform' \| 'classic'`), `showShuffle`, `shuffle` |
| Theming | `defaultArtwork` (`string \| null`), `theme` (`'dark' \| 'light' \| null`) |
| Waveform | `waveform` (boolean), `waveformStyle`, `waveformHeight`, `barWidth`, `barSpacing`, `barRadius`, `waveformColor`, `progressColor`, `waveformGradient`, `markerColor` |
| Sharing / errors | `share`, `shareParam`, `errorText`, `crossOrigin` |
| Player strings | `seekValueText`, `unknownTrackText`, `playPauseLabel`, `speedLabel`, `artworkAlt` (forwarded to the embedded player) |
| Volume / storage | `volume`, `storageKey` |
| Server actions | `actions` (`{ favorite?, cart? }`, each `{ endpoint, method?, headers? }`) |

:::note[`mode` picks the layout]
`mode` defaults to `'waveform'` (the standard layout with a width-adjustable waveform canvas — pair it with `wide` to span the viewport). Set `mode: 'classic'` for a Spotify-style centre layout with a full-width seek bar instead of the waveform. There is no `maxWidth` field — width is controlled by `wide` and `mode`.
:::

### Trigger a track

`<WaveformBarTrigger>` emits the `data-wb-*` attribute contract the bar scans for; the core library handles click delegation. It is polymorphic via `as` — a `<button>` by default — and forwards every standard DOM attribute (`onclick`, `data-testid`, `role`, …) to the rendered element via `...rest`.

```svelte
<script lang="ts">
  import { WaveformBarTrigger } from '@arraypress/waveform-svelte/bar';
  let { track } = $props();
</script>

<article>
  <h3>{track.title}</h3>

  <!-- Default: a <button> with auto play/pause icons -->
  <WaveformBarTrigger
    url={track.url}
    id={track.id}
    title={track.title}
    artist={track.artist}
    artwork={track.cover}
    duration={track.seconds}
  />

  <!-- Append to the queue with custom content -->
  <WaveformBarTrigger mode="queue" url={track.url} title={track.title}>
    + Queue
  </WaveformBarTrigger>

  <!-- Wrap a whole card as the trigger -->
  <WaveformBarTrigger as="div" url={track.url} title={track.title} noDefaultIcons>
    <div class="card-body"><!-- … --></div>
  </WaveformBarTrigger>
</article>
```

**Track data props** (`WaveformBarTrackData`) — each maps 1:1 to a `data-wb-*` attribute; arrays are JSON-encoded, and absent props emit no attribute:

| Prop | Type | Notes |
| --- | --- | --- |
| `url` | `string` | Play target + identity. |
| `id` | `string` | Defaults to `url`. |
| `title`, `artist`, `album`, `artwork`, `link` | `string` | Display metadata. |
| `duration` | `string \| number` | Seconds (`187`) or a clock string (`'3:07'`, `'1:02:03'`). The 2.0 bar shows it as soon as the track loads and passes it to the player as its `duration`. |
| `bpm` | `string \| number` | |
| `musicalKey` | `string` | → `data-wb-key`. |
| `meta` | `string[]` | Extra metadata chips. |
| `waveform` | `number[] \| string` | Pre-computed peaks: an array, a `.json` URL, or compact `wp1:` peaks. |
| `markers` | `WaveformBarMarker[]` | DJ-mode cue markers (`{ time, label, title?, artist?, artwork?, bpm?, key?, color? }`). |
| `favorited`, `inCart` | `boolean` | Initial action state. |

**Trigger-specific props:**

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `mode` | `'play' \| 'queue'` | `'play'` | Immediate play vs. append to queue. |
| `as` | `'button' \| 'a' \| 'div' \| 'span'` | `'button'` | Rendered tag. |
| `href` | `string` | — | Used when `as="a"`. |
| `noDefaultIcons` | `boolean` | `false` | Suppress the injected play/pause SVGs. |
| `aria-label` | `string` | auto | Auto-generated from `title` when absent. |
| `class` | `string` | — | Appended to the base class `wb-icon-swap`. |

Slotted children replace the default icons. `class`, native listeners (`onclick`), and any other DOM attribute fall through to the rendered element.

:::note[No callback props on the bar]
The bar deliberately exposes no callback props (and no imperative handle) — an inline function each render would needlessly re-init the singleton. The core dispatches every state change as a bubbling `waveformbar:*` `CustomEvent` (e.g. `waveformbar:play`, `waveformbar:trackchange`); listen via `addEventListener` in your own effect. That stays framework-agnostic and avoids re-init churn.
:::

  continuous

  tracks={[

### `tracks` (required)

`WaveformPlaylistTrackInput[]`:

| Field | Type | Notes |
| --- | --- | --- |
| `url` | `string` | **Required** → `data-url`. |
| `title` | `string` | Falls back to the filename if omitted. |
| `artist` | `string` | Artist row. |
| `artwork` | `string` | Artwork URL. |
| `album` | `string` | Media Session metadata. |
| `duration` | `number \| string` | Seconds (`225`) or a clock string (`'3:45'`, `'1:02:03'`) → `data-duration`. Shown in the list (seconds are formatted) and passed to the player as its `duration`, so the time readout, markers and seeks work before the audio loads. |
| `downloadUrl` | `string` | This track's download link (`data-download-url`), shown with `showDownload`. Defaults to the track's `url`. |
| `downloadName` | `string` | Suggested file name (`data-download-name`). Defaults to the url's file name. |
| `waveform` | `number[] \| string` | Pre-computed peaks: an array (JSON-encoded into `data-waveform`), a `.json` URL, or compact `wp1:` peaks. |
| `markers` | `WaveformPlaylistMarker[]` | JSON-encoded into `data-markers`. |
| `chapters` | `WaveformPlaylistChapterInput[]` | `{ time: number \| string, label, color? }` — `time` accepts seconds or `'M:SS'`. |

### Props

`WaveformPlaylistProps` combines three groups:

1. **Playlist options** picked from `WaveformPlaylistOptions`: `continuous`, `expandChapters`, `showDuration`, `showChapterMarkers`, `chapterMarkerColor`, `showPlayState`, and the layout options `layout`, `showArtist`, `coverSize`, `thumbnailSize`, `density`, `coverPosition`, `barPosition` (see [Playlist → Options](/extensions/playlist/options/)).
2. **Pass-through player options** — the full `WaveformPlayerOptions` visualization / colour / behaviour surface, including the 2.0 `showVolume`, `volume`, `showDownload`, `volumeLabel`, `muteLabel` and `downloadLabel`, **minus** per-track content (`url`, `src`, `title`, `artist`, `artwork`, `album`, `markers`, `waveform`, `duration`, `downloadUrl`, `downloadName` — set those on each track), the `style` alias, the player's own `layout`, the options the playlist never passes to its player (below), and the lifecycle callbacks.
3. **Svelte extras** — the required `tracks`, plus `class`, `style`, `id` and other element attributes (fall through to the host).

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `tracks` | `WaveformPlaylistTrackInput[]` | — | **Required.** An empty array renders an empty playlist (the core skips init). |
| `layout` | `'list' \| 'minimal' \| 'hero' \| 'grid'` | `'list'` | Full track list, compact button switcher, now-playing hero over a queue, or cover-art grid. **Overrides** the player's own `layout`. |
| `class` | `string` | — | Appended to `wfp-host`. |
| `style` | `string` | — | Inline CSS on the host. |
| `id` | `string` | — | Forwarded to the host `<div>`. |

Common pass-through player props include `waveformStyle`, `height`, `colorPreset`, `waveformColor`, `progressColor`, `showBPM`, `accessibleSeek`, `autoplay`, `showVolume` and `showDownload` — see [Player → Options](/player/options/) for the complete list.

:::note[Not playlist props]
`audioMode`, `loop`, `showLoop`, `loopLabel` and `lazy` are **not** props: the playlist always owns its audio, a looping track never ends (which stops `continuous`), and `lazy` would only defer the playlist's own player. Neither are the per-track `duration`, `downloadUrl` and `downloadName` — set them on each track. A stray one is swallowed: never forwarded, never on the host element.
:::

The lowercase lifecycle callback props `onload`, `onplay`, `onpause`, `onend`, `ontimeupdate`, `onerror`, `onnexttrack` and `onprevioustrack` are accepted and forwarded to the embedded player (the playlist runs each after its own handling); like the player's, they reach the live instance through reactive closures and never trigger a re-mount. The player's 2.0 event props (`onseek`, `onratechange`, `onvolumechange`, `onloop`) are not — the embedded player's [`waveformplayer:*` events](/player/events/) bubble, so listen for them on an element wrapping the playlist.

| Method | Signature | Notes |
| --- | --- | --- |
| `selectTrack` | `(index: number) => void` | Select + load a track by index. |
| `seekToChapter` | `(trackIndex, time) => void` | Loads the target track first if needed, then seeks. |
| `nextTrack` | `() => void` | |
| `previousTrack` | `() => void` | |

## Sounds — `<WaveformSounds>`

A searchable, filterable list of sound previews — a sample pack, a preset bank — with a mini waveform per row and one shared audio engine. With `sounds`, the list is **rendered on the server** by the core's own DOM-free renderer, hydration keeps those nodes, and the runtime adopts them instead of rebuilding. See [WaveformSounds](/extensions/sounds/) for what the list does.

### Quick start

```svelte
<script lang="ts">
  import { WaveformSounds } from '@arraypress/waveform-svelte/sounds';
  import pack from '$lib/sounds.json'; // written by waveform-gen --manifest
</script>

<WaveformSounds sounds={pack.sounds} onplay={(sound) => console.log(sound.title)} />

<!-- or, fetched and built in the browser: -->
<WaveformSounds manifest="/sounds.json" />
```

Write the JSON with [`waveform-gen --manifest`](/extensions/gen/manifest/) — mind its `--base-url`, which has to match where the audio is served.

### Props

Every `WaveformSoundsOptions` key except the callbacks is a prop, typed from the core's declarations (`WaveformSoundsProps`) — `sounds` / `manifest`, `player`, `search`, `filters`, `sorts`, `showCount`, `menuSearch`, `idPrefix`, `urlState`, `loopToggle`, `maxTypeChips`, `mergeEnharmonicKeys`, `pageSize`, `columns`, `waveformStyle`, `waveformColor`, `progressColor`, `barWidth`, `barGap`, `loop`, `autoAdvance`, `arrowAudition`, `playerOptions`, `playerClass`, `strings`. See [Options](/extensions/sounds/options/) for each one. `class`, `id`, `style` and any other attribute land on the host `<div>`. The sound list's API is unchanged in 2.0; a sound's `duration` now also reaches the engine, and `playerOptions` can't turn on the player's `loop` / `showLoop`.

The callbacks are **lowercase props** — `onready`, `onplay`, `onpause`, `onend`, `onfilter`, `onerror` — with the core callbacks' arguments. They reach the live instance through closures, so a new handler never rebuilds the list. The core's bubbling [`waveformsounds:*` events](/extensions/sounds/api/#events) fire from the host too.

- **`mergeEnharmonicKeys`** (2.2.0+, default `true`): A#m and Bbm, C# and Db are one key-menu entry. It is forwarded to the runtime and shapes the server markup through the core's `pickRenderOptions()`, so `mergeEnharmonicKeys={false}` keeps the spellings apart on the server and after hydration. See [Enharmonic keys](/extensions/sounds/features/#enharmonic-keys).
- **Server markup.** With `sounds`, the host's `{@html}` is the core's [`renderSounds()`](/extensions/sounds/api/#server-rendering-render) output — the list's 2.2 markup: only the rows it starts with (the first page), each carrying just `data-ws-index`, and every sound once in an inert `<script type="application/json" data-ws-sounds>`. Read a row's sound from the instance (`instance.sounds[Number(row.dataset.wsIndex)]`) or an event's `sound`, not from row attributes — rows no longer carry `data-title`, `data-url` and the rest. It hydrates without a mismatch, and icons are one sprite per list.
- **Dropdown ids**: `idPrefix`, else the host's `id`, else a per-component id from `$props.id()` — unique, and identical on the server and during hydration.
- **`urlState`** is runtime-only: the server renders the unfiltered list and the runtime applies the address after hydration.
- **Any change to `sounds` or an option rebuilds the list** over a fresh render, so the new instance never adopts rows the old one re-sorted or hid. A `class`-only change doesn't rebuild.

Theme it through `style` — set `--ws-surface` (your page background) so the server-rendered first paint is right:

```svelte
<WaveformSounds {sounds} style="--ws-surface: #0b0b0c" />
```

## Server-side rendering

All four components are SSR / SvelteKit-prerender safe by construction: the host markup (for the playlist, the `[data-track]` children; for the sound list, its toolbar, first page of rows and sound data when given `sounds`) renders on the server, and the browser-only core is dynamically `import()`ed inside `$effect`. Because effects never run during SSR, the audio + canvas surface only evaluates after hydration on the client — no `import.meta.env.SSR` guard or `{#if browser}` wrapper is needed.

Reserve layout space with the `style` attribute (e.g. `style="min-height: 96px"`) to avoid a content shift before the waveform draws, and import each core's CSS once in your root `+layout.svelte` (for the bar and playlist, remember to import the player core too). For long pages of players, add `lazy` and `duration` so off-screen players cost nothing until they're needed — see [Lazy loading](/player/lazy-loading/) and [Zero-bandwidth players](/player/zero-bandwidth/).
