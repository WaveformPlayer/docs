One package, `@arraypress/waveform-vue`, ships typed Vue 3 components for the whole `@arraypress` waveform family. Each core has its own sub-path, so you install only the cores of the components you use:

| Import from | Component(s) | Install with it |
| --- | --- | --- |
| `@arraypress/waveform-vue/player` | `<WaveformPlayer>` | [`@arraypress/waveform-player`](/player/options/) |
| `@arraypress/waveform-vue/bar` | `<WaveformBar>`, `<WaveformBarTrigger>` | [`@arraypress/waveform-bar`](/extensions/bar/), `@arraypress/waveform-player` |
| `@arraypress/waveform-vue/playlist` | `<WaveformPlaylist>` | [`@arraypress/waveform-playlist`](/extensions/playlist/), `@arraypress/waveform-player` |
| `@arraypress/waveform-vue/sounds` | `<WaveformSounds>` | [`@arraypress/waveform-sounds`](/extensions/sounds/), `@arraypress/waveform-player` |

There is no root import — `import … from '@arraypress/waveform-vue'` does not resolve. Each sub-path loads its core lazily with `import()`, and bundlers resolve every `import()` at build time, so a single entry for all four would fail to build for anyone who hadn't installed every core.

:::note[Coming from 1.x]
The four separate Vue wrappers are replaced by sub-paths of the one package. Each sub-path exports the same components, props, emits, exposed API and types as the package it replaces, so switching is a change of import path (plus the [2.0 cores](/getting-started/migrating-from-1x/)):

| Before | Now |
| --- | --- |
| `@arraypress/waveform-player-vue` | `@arraypress/waveform-vue/player` |
| `@arraypress/waveform-bar-vue` | `@arraypress/waveform-vue/bar` |
| `@arraypress/waveform-playlist-vue` | `@arraypress/waveform-vue/playlist` |
| `@arraypress/waveform-sounds-vue` | `@arraypress/waveform-vue/sounds` |

The old packages are deprecated; their last releases keep working with the 1.x cores. See [Migrating from 1.x](/getting-started/migrating-from-1x/).
:::

**Requirements:** Vue 3.5+ (`vue` peer `^3.5.0`). The cores are **optional** peer dependencies at `^2.0.0` — install the ones your sub-paths need, per the table above. The package is ES modules only (Node 22.12+ loads it through `require()` if you must), and building with it needs Node 22.12+. The 2.0 cores run on Chrome/Edge 111+, Firefox 114+ and Safari 16.4+.

Every component follows the same design:

- **Each is a `defineComponent`** with a render function — no `.vue` compile step, and generated `.d.ts` types (`typesVersions` keeps every sub-path's types visible to TypeScript's `moduleResolution: "node"`). Core options surface as **props**, lifecycle events as **emits**, and the instance as a **template ref**.
- **Prop types are derived from the core's own typings** (`WaveformPlayerOptions`; `WaveformPlaylistOptions`; `WaveformSoundsOptions` for the sound list), not re-declared — the 2.0 cores generate their declarations from their TypeScript source, so the props never drift as the core evolves.
- **The core JS is dynamically `import()`ed inside `onMounted`**, so the audio + canvas + `fetch` surface never runs during SSR / Nuxt.
- **Every optional prop is declared `{ type: …, default: undefined }`.** An absent prop is *never forwarded* to the core, so the core's own default applies — you only pass the props you want to override.
- **CSS is never auto-loaded** — you import each core's stylesheet once at your app entry.

:::caution[Use `waveformStyle`, not `style`]
On all four components, `style` (and `class`, `id`) is a standard HTML attribute forwarded to the host `<div>` — use it to reserve layout height, etc. The base class (`wfp-host` / `wb-host`) is always merged in. The core's `style` alias for the *visual* waveform style is intentionally omitted from the prop type. To pick a visual style use **`waveformStyle`** / `waveform-style` (`'bars' | 'mirror' | 'line' | 'blocks' | 'dots' | 'seekbar'`).
:::

Import the core stylesheet **once** at your app entry:

```ts
// main.ts / app entry
import '@arraypress/waveform-player/dist/waveform-player.css';
```

The component loads the core's [`/no-autoinit` entry point](/player/data-attributes/#if-you-dont-control-the-page-either), so mounting it never scans the page for markup it doesn't own.

### Quick start

```vue
<script setup lang="ts">
import { WaveformPlayer } from '@arraypress/waveform-vue/player';
</script>

<template>
  <WaveformPlayer
    url="/audio/track.mp3"
    title="My Track"
    waveform-style="mirror"
    :waveform-color="['#fafafa', '#71717a']"
    show-bpm
    @timeupdate="(currentTime, duration) => { /* live progress */ }"
  />
</template>
```

`src` is the core's shorthand alias for `url` (`url` wins if both are set). Provide one of the two.

With a known length and compact peaks, a `preload="none"` player shows the total time and the waveform without fetching any audio until play — see [Zero-bandwidth players](/player/zero-bandwidth/):

```vue
<WaveformPlayer
  url="/audio/track.mp3"
  preload="none"
  :duration="187"
  waveform="wp1:…"
  show-volume
  show-download
/>
```

### Props

Every core player option is accepted as a typed prop — `url`, `src`, `audioMode`, `preload`, `height`, `samples`, `barWidth`, `barSpacing`, `barRadius`, `colorPreset`, gradient-array colours (`waveformColor`, `progressColor`), `accessibleSeek`, `markers`, `showBPM`, and so on. The prop type `WaveformPlayerProps` is `Omit<WaveformPlayerOptions, 'style' | …callbacks>`, so it tracks the core automatically. See [Player → Options](/player/options/) for the full inherited surface.

New with the 2.0 core:

| Prop | Type | Notes |
| --- | --- | --- |
| `duration` | `number` | The track's length in seconds, shown and used for seeks until the audio's metadata arrives. See [Zero-bandwidth players](/player/zero-bandwidth/). |
| `lazy` | `boolean` | Defer loading the audio and peaks until the player nears the viewport. See [Lazy loading](/player/lazy-loading/). |
| `loop`, `showLoop`, `loopLabel` | `boolean`, `boolean`, `string` | Whole-track looping and a loop toggle (self mode). See [Looping](/player/looping/). |
| `showVolume`, `volume`, `volumeLabel`, `muteLabel` | `boolean`, `number`, `string`, `string` | Mute toggle + volume slider; `volume` is the initial `0..1` (self mode). |
| `showDownload`, `downloadUrl`, `downloadName`, `downloadLabel` | `boolean`, `string`, `string`, `string` | A download link; `downloadUrl` defaults to the track url, `downloadName` to its file name. |
| `waveform` | `number[] \| string` | Now also accepts compact `wp1:` peaks, passed through for the core to decode. |

`duration`, `downloadUrl` and `downloadName` are per-track: the component remounts when `url` changes, so set each together with the `url` it belongs to.

Because every optional prop defaults to `undefined`, props you don't pass are not forwarded and the core's default wins.

### Events

The six core lifecycle callbacks surface as **emits** (not callback props), each forwarding the live `WaveformPlayer` instance. The four 2.0 state-change events carry the `detail` of the core's `waveformplayer:<name>` [event](/player/events/). Emits are typed, so listeners are typed in templates:

```vue
<WaveformPlayer
  url="/audio/track.mp3"
  @load="(player) => console.log('loaded', player)"
  @play="() => console.log('playing')"
  @pause="() => console.log('paused')"
  @timeupdate="(currentTime, duration) => console.log(`${currentTime} / ${duration}`)"
  @end="() => console.log('finished')"
  @error="(err) => console.error('audio failed:', err)"
  @seek="(d) => console.log('seeked to', d.currentTime)"
  @volumechange="(d) => save(d.volume, d.muted)"
/>
```

| Emit | Payload | Notes |
| --- | --- | --- |
| `@load` | `(instance)` | Fired after the waveform is drawn. |
| `@play` | `(instance)` | Playback started (both audio modes). |
| `@pause` | `(instance)` | Playback paused (both modes). |
| `@end` | `(instance)` | Track ended (external mode synthesizes it at progress ≥ 1). |
| `@timeupdate` | `(currentTime, duration, instance)` | Progress tick. Same argument order in both modes. |
| `@error` | `(error, instance)` | Load / decode / audio error. |
| `@seek` | `(detail: WaveformSeekEventDetail)` | `{ player, url, currentTime, duration }` — any seek, and a whole-track loop's wrap. Self mode only. |
| `@ratechange` | `(detail: WaveformRateChangeEventDetail)` | `{ player, url, playbackRate }`. Self mode only. |
| `@volumechange` | `(detail: WaveformVolumeChangeEventDetail)` | `{ player, url, volume, muted }`. Self mode only. |
| `@loop` | `(detail: WaveformLoopEventDetail)` | `{ player, url, loop, start, end }` — `start` / `end` are the section loop, or `null`. Self mode only. |

The detail types are re-exported from `@arraypress/waveform-vue/player` (with `AudioCrossOrigin`).

**Media Session track navigation:** `@next-track` / `@previous-track` (the `onNextTrack` / `onPreviousTrack` props) receive the instance. Supplying one shows the lock-screen / system media controls' skip button, so they are function props rather than emits — the component has to know whether anyone is listening. Adding or removing one remounts the player; swapping one handler for another doesn't.

`emit` is stable, so listeners always reach the latest handler without tearing the player down. Only construction-time props (`url`, `audioMode`, visualization options, …) trigger a re-mount.

### Imperative API

Grab the instance with a template `ref` typed as `WaveformPlayerExpose`. Methods are reached through `defineExpose`:

```vue
<script setup lang="ts">
import { ref } from 'vue';
import {
  WaveformPlayer,
  type WaveformPlayerExpose,
} from '@arraypress/waveform-vue/player';

const player = ref<WaveformPlayerExpose>();
</script>

<template>
  <WaveformPlayer ref="player" url="/audio/track.mp3" />
  <button @click="player?.togglePlay()">Play / Pause</button>
  <button @click="player?.seekTo(60)">Jump to 1:00</button>
  <button @click="player?.loadTrack('/audio/next.mp3', 'Next Track', 'Artist')">
    Load next
  </button>
</template>
```

| Method | Signature | Notes |
| --- | --- | --- |
| `play` | `() => Promise<void> \| undefined` | Returns the native `play()` promise in self mode; `undefined` in external mode. |
| `pause` | `() => void` | |
| `togglePlay` | `() => void` | |
| `seekTo` | `(seconds: number) => void` | Self mode only. |
| `seekToPercent` | `(percent: number) => void` | Fraction `0..1`. Self mode only. |
| `setVolume` | `(volume: number) => void` | `0..1`. Self mode only. |
| `setPlaybackRate` | `(rate: number) => void` | Clamped `0.25..4`. Self mode only. |
| `setPlayingState` | `(playing: boolean) => void` | **External mode** — push play/pause visual state. |
| `setProgress` | `(currentTime, duration) => void` | **External mode** — push the progress overlay from your own clock. |
| `loadTrack` | `(url, title?, artist?, options?) => Promise<void>` | Swap track at runtime; auto-plays unless `options.autoplay === false`. |
| `instance` | `readonly WaveformPlayer \| null` | Escape hatch — full core API (`getVolume`, `setMuted`, `load`, `setWaveformData`, `refreshTheme`, `container`, statics, …). See [Methods](/player/methods/). |

Calls before the async import resolves are safe no-ops.

:::note[Re-mount semantics]
When any construction prop changes, the component destroys the instance and constructs a new one rather than diffing options. Same-`url` re-mounts are cheap because the core caches decoded peaks keyed by URL. For runtime track swaps without a re-mount, use `loadTrack()`. (A `:key` bound to the URL forces the same clean rebuild explicitly.)
:::

:::tip[DOM events]
Prefer the emits. If you need another raw `waveformplayer:*` [event](/player/events/) (e.g. `waveformplayer:request-seek` in external mode), attach via the instance: `player.value?.instance?.container.addEventListener(...)`.
:::

:::tip[The `<waveform-player>` element]
The 2.0 core also ships a [`<waveform-player>` custom element](/player/element/). The component above is the better fit inside a Vue app (typed props, emits, SSR-safe loading). If you do use the element in a template, tell Vue it isn't a component (`compilerOptions.isCustomElement: (tag) => tag === 'waveform-player'` in your Vue plugin config) so it doesn't warn.
:::

:::caution[Load order matters]
The bar has a hard runtime dependency on the player global. Import the **player before the bar** at your app entry, or `window.WaveformBar` will be undefined:

```ts
import '@arraypress/waveform-player/dist/waveform-player.css';
import '@arraypress/waveform-bar/dist/waveform-bar.css';
import '@arraypress/waveform-player'; // sets window.WaveformPlayer  (first)
import '@arraypress/waveform-bar';    // sets window.WaveformBar     (second)
```
:::

### Mount the bar

```vue
<script setup lang="ts">
import { WaveformBar } from '@arraypress/waveform-vue/bar';
</script>

<template>
  <RouterView />
  <WaveformBar
    :config="{
      persist: true,
      continuous: true,
      showQueue: true,
      actions: {
        favorite: { endpoint: '/api/favorites' },
        cart: { endpoint: '/api/cart' },
      },
    }"
  />
</template>
```

On mount the component dynamically imports the core and calls `window.WaveformBar.init(config)`. When the config's structural shape changes it re-runs `init()` (idempotent — the library destroys and recreates internally); on unmount it calls `destroy()` so route changes and HMR reloads don't leak listeners.

| `<WaveformBar>` prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `config` | `WaveformBarConfig` | `undefined` | Passed verbatim to `init()`. See table below. |
| `persist` | `boolean` | `true` | Relocate the `.waveform-bar` element under the host `<div>` so it survives route changes. |
| `hostId` | `string` | `'waveform-bar-host'` | DOM `id` of the persist host. |

`class` and `style` fall through to the persist host `<div>` (base class `wb-host`).

:::note[Config change detection]
The config is compared by a `JSON.stringify` key, so passing a fresh object with the same shape every render is safe. Function endpoints (`actions.*.endpoint`) serialize to a placeholder, so if you pass a function endpoint, keep the whole `config` reference stable (hoist it or wrap it in a `computed`) to avoid re-init churn.
:::

#### `WaveformBarConfig`

Declared by this package (it reads `window.WaveformBar` through its own structural type and declares nothing global, so it can't conflict with the 2.0 bar's own types). Every field is optional; see [Bar → Configuration](/extensions/bar/configuration/) for each one.

| Group | Fields |
| --- | --- |
| Behaviour | `persist`, `autoResume`, `continuous`, `repeat` (`'off' \| 'all' \| 'one'`), `shuffle` |
| UI toggles | `showQueue`, `showPrevNext`, `showRepeat`, `showShuffle`, `showVolume`, `showMute`, `showTime`, `showTrackLink`, `showMeta`, `maxMeta` (number) |
| Layout | `mode` (`'waveform' \| 'classic'`), `wide`, `position` (`'bottom' \| 'top'`), `collapsible` |
| Theming | `defaultArtwork` (`string \| null`), `theme` (`'dark' \| 'light' \| null`) |
| Waveform | `waveform` (boolean), `waveformStyle`, `waveformHeight`, `barWidth`, `barSpacing`, `barRadius`, `waveformColor`, `progressColor`, `waveformGradient`, `markerColor` |
| Sharing / errors | `share`, `shareParam`, `errorText` |
| Audio | `crossOrigin` (`'anonymous' \| 'use-credentials' \| null`) |
| Player strings | `seekValueText`, `unknownTrackText`, `playPauseLabel`, `speedLabel`, `artworkAlt` (forwarded to the embedded player) |
| Volume / storage | `volume`, `storageKey` |
| Server actions | `actions` (`{ favorite?, cart? }`, each `{ endpoint, method?, headers? }`) |

`mode` defaults to `'waveform'` (the standard layout with a width-adjustable waveform). Set `mode: 'classic'` for the Spotify-style centre layout with a full-width seek bar. `showShuffle` adds a shuffle toggle to the transport cluster; `shuffle` starts with random queue advance on.

### Trigger a track

`<WaveformBarTrigger>` emits the `data-wb-*` attribute contract the bar scans for. It is polymorphic — a `<button>` by default — and any unlisted DOM attribute or native listener (`@click`, `data-testid`, `role`, …) falls through to the rendered element.

```vue
<script setup lang="ts">
import { WaveformBarTrigger } from '@arraypress/waveform-vue/bar';
</script>

<template>
  <!-- Default: a <button> with auto play/pause icons -->
  <WaveformBarTrigger
    url="/audio/track.mp3"
    id="track-42"
    title="Midnight Dreams"
    artist="The Wavelength"
    artwork="/img/cover.jpg"
    :duration="187"
  />

  <!-- Append to the queue with custom content -->
  <WaveformBarTrigger mode="queue" url="/audio/track.mp3" title="Midnight Dreams">
    + Queue
  </WaveformBarTrigger>

  <!-- Wrap a whole card as the trigger -->
  <WaveformBarTrigger as="div" :url="track.url" no-default-icons>
    <article class="product-card">…</article>
  </WaveformBarTrigger>
</template>
```

**Track data props** (`WaveformBarTrackData`) — each maps 1:1 to a `data-wb-*` attribute; arrays are JSON-encoded and absent props emit no attribute:

| Prop | Type | Notes |
| --- | --- | --- |
| `url` | `string` | **Required** — play target + identity. |
| `id` | `string` | Defaults to `url`. |
| `title`, `artist`, `album`, `artwork`, `link` | `string` | Display metadata. |
| `duration` | `string \| number` | Seconds (`187`) or a clock string (`'3:07'`, `'1:02:03'`). The 2.0 bar shows it and passes it to the player as its `duration`, so the length shows before any audio loads. |
| `bpm` | `string \| number` | |
| `musicalKey` | `string` | → `data-wb-key`. |
| `meta` | `string[]` | Extra metadata chips. |
| `waveform` | `number[] \| string` | Pre-computed peaks: an array, compact `wp1:` peaks, or a `.json` URL. |
| `markers` | `WaveformBarMarker[]` | DJ-mode cue markers (`{ time, label, title?, artist?, artwork?, bpm?, key?, color? }`). |
| `favorited`, `inCart` | `boolean` | Initial action state. |

**Trigger-specific props:**

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `mode` | `'play' \| 'queue'` | `'play'` | Immediate play vs. append to queue. |
| `as` | `'button' \| 'a' \| 'div' \| 'span'` | `'button'` | Rendered tag. |
| `href` | `string` | — | Used when `as="a"`. |
| `noDefaultIcons` | `boolean` | `false` | Suppress the injected play/pause SVGs. |
| `aria-label` | `string` | auto | Falls through to the element; auto-generated from `title` when absent. |
| default slot | — | — | Custom content; overrides the default icons. |

`class` is merged with the base class `wb-icon-swap`.

:::note[No callback props on the bar]
The bar deliberately exposes no emits and no imperative ref — an inline function each render would re-init the singleton. The core dispatches every state change as a bubbling `waveformbar:*` `CustomEvent` (`waveformbar:play`, `waveformbar:trackchange`, …); listen via `addEventListener` in your own effect. That stays framework-agnostic and avoids re-init churn.
:::

### Quick start

```vue
<script setup lang="ts">
import { WaveformPlaylist } from '@arraypress/waveform-vue/playlist';

const tracks = [
  { url: '/audio/a.mp3', title: 'Track A', artist: 'Artist', duration: 225 },
  {
    url: '/audio/b.mp3',
    title: 'Track B',
    duration: '3:45',
    chapters: [
      { time: 0, label: 'Intro' },
      { time: '1:30', label: 'Verse' },
      { time: 180, label: 'Chorus', color: '#22d3ee' },
    ],
  },
];
</script>

<template>
  <WaveformPlaylist continuous waveform-style="bars" :tracks="tracks" />
</template>
```

Each track renders into the `[data-track]` / `[data-chapter]` markup the playlist constructor parses on mount. The host carries the base class `wfp-host`.

### `tracks` (required)

`WaveformPlaylistTrackInput[]`:

| Field | Type | Notes |
| --- | --- | --- |
| `url` | `string` | **Required** → `data-url`. |
| `title` | `string` | Falls back to the filename if omitted. |
| `artist` | `string` | Artist row. |
| `artwork` | `string` | Artwork URL. |
| `album` | `string` | Media Session metadata. |
| `duration` | `number \| string` | Seconds (`225`) or a clock string (`'3:45'`). The list shows it, and the 2.0 playlist hands it to the player as its `duration`, so the time readout and seeks have a length before the audio's metadata loads. |
| `downloadUrl` | `string` | This track's download link (`data-download-url`), shown with `showDownload`. Defaults to `url`. |
| `downloadName` | `string` | Suggested download file name (`data-download-name`). Defaults to the url's. |
| `waveform` | `number[] \| string` | Pre-computed peaks, so the player skips decoding: an array (JSON-encoded), compact `wp1:` peaks, or a `.json` URL. |
| `markers` | `WaveformPlaylistMarker[]` | JSON-encoded into `data-markers`. |
| `chapters` | `WaveformPlaylistChapterInput[]` | `{ time: number \| string, label, color? }` — `time` accepts seconds or `'M:SS'`. |

### Props

`WaveformPlaylistProps` combines three groups:

1. **Playlist options** picked from `WaveformPlaylistOptions`: `continuous`, `expandChapters`, `showDuration`, `showChapterMarkers`, `chapterMarkerColor`, `showPlayState`, plus the layout options (`WaveformPlaylistLayoutProps`): `layout`, `showArtist`, `coverSize`, `thumbnailSize`, `density`, `coverPosition`, `barPosition`.
2. **Pass-through player options** — the `WaveformPlayerOptions` visualization / colour / behaviour surface the playlist hands its player, including 2.0's `showVolume`, `volume`, `showDownload`, `volumeLabel`, `muteLabel` and `downloadLabel`.
3. **Vue extras** — the required `tracks` (plus `class`, `style`, `id` falling through to the host).

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `tracks` | `WaveformPlaylistTrackInput[]` | `[]` | **Required.** An empty array renders an empty playlist (the core skips init). |
| `layout` | `'list' \| 'minimal' \| 'hero' \| 'grid'` | `'list'` | Full track list, compact button switcher, now-playing hero over a queue, or a cover-art grid. **Overrides** the player's own `layout`. |
| `showArtist` | `boolean` | `true` | Show the now-playing / per-row artist. |
| `coverSize`, `thumbnailSize` | `number` | — | Hero cover / queue thumbnail (and grid cover) size in px. |
| `density` | `'comfortable' \| 'compact'` | `'comfortable'` | Row density for every layout. |
| `coverPosition` | `'left' \| 'top'` | `'left'` | Hero / grid cover position. |
| `barPosition` | `'top' \| 'bottom'` | `'bottom'` | Grid layout's now-playing bar. |

Common pass-through player props include `waveformStyle`, `height`, `colorPreset`, `waveformColor`, `progressColor`, `showBPM`, `accessibleSeek`, `autoplay`, `showVolume` and `showDownload` — see [Player → Options](/player/options/) and [Playlist → Options](/extensions/playlist/options/).

:::note[Not props on the playlist]
Some player options aren't playlist props, because the 2.0 playlist never passes them to its player: `audioMode` (it owns its audio), `loop` and `showLoop` (a looping track never ends, which would stop `continuous`), `lazy` (it loads its own player) and `loopLabel`. Per-track content — `url`, `title`, `artist`, `artwork`, `album`, `markers`, `waveform`, `duration`, `downloadUrl`, `downloadName` — comes from `tracks`, not props.
:::

### Events

The embedded player's callbacks surface as emits with the core's arguments, the same idiom as `<WaveformPlayer>`. The playlist runs each after its own handling (continuous playback, chapter tracking), and `emit` is stable, so a new listener never re-mounts the playlist.

| Emit | Payload |
| --- | --- |
| `@load` / `@play` / `@pause` / `@end` | `(player)` |
| `@timeupdate` | `(currentTime, duration, player)` |
| `@error` | `(error, player)` |
| `@nexttrack` / `@previoustrack` | `(player)` — Media Session skip buttons. |

`player` is the embedded `WaveformPlayer` instance.

### Imperative API

Grab the instance with a template `ref` typed as `WaveformPlaylistExpose`:

```vue
<script setup lang="ts">
import { ref } from 'vue';
import {
  WaveformPlaylist,
  type WaveformPlaylistExpose,
} from '@arraypress/waveform-vue/playlist';

const playlist = ref<WaveformPlaylistExpose>();
</script>

<template>
  <WaveformPlaylist ref="playlist" :tracks="tracks" continuous />
  <button @click="playlist?.previousTrack()">Prev</button>
  <button @click="playlist?.nextTrack()">Next</button>
  <button @click="playlist?.selectTrack(0)">First</button>
</template>
```

| Method | Signature | Notes |
| --- | --- | --- |
| `selectTrack` | `(index: number) => void` | Select + load a track by index. |
| `seekToChapter` | `(trackIndex, time) => void` | Loads the target track first if needed, then seeks. |
| `nextTrack` | `() => void` | |
| `previousTrack` | `() => void` | |
| `getPlayer` | `() => unknown \| null` | The embedded `WaveformPlayer` instance (full player API). |
| `getCurrentTrackIndex` | `() => number` | |
| `getTracks` | `() => WaveformPlaylistTrack[]` | Parsed tracks (with resolved `element` / `index`). |
| `instance` | `readonly WaveformPlaylist \| null` | Escape hatch for anything else. |

Calls before the async import resolves are no-ops.

:::note[Re-mount semantics]
Changing `tracks` (compared by serialized value) or any construction-time option tears the playlist down and rebuilds it against the freshly rendered markup. The watcher uses `flush: 'post'` so the new track markup is in the DOM before the constructor re-parses it. For navigation without a re-mount, use the handle above.
:::

## Sounds — `<WaveformSounds>`

A searchable, filterable list of sound previews — a sample pack, a preset bank — with a mini waveform per row and one shared audio engine. With `sounds`, the list's markup is **rendered on the server too** (Nuxt, `vue/server-renderer`) by the core's DOM-free renderer, and the runtime adopts it instead of rebuilding. See [WaveformSounds](/extensions/sounds/) for what the list does.

### Quick start

```vue
<script setup lang="ts">
import { WaveformSounds } from '@arraypress/waveform-vue/sounds';
</script>

<template>
  <WaveformSounds manifest="/sounds.json" @play="(sound) => console.log(sound.title)" />
</template>
```

Write `sounds.json` with [`waveform-gen --manifest`](/extensions/gen/manifest/) — mind its `--base-url`, which has to match where the audio is served. With a `manifest` the list is fetched and built in the browser; pass a `:sounds` array instead to render it on the server. A `sounds` array — even an empty one — wins over `manifest`.

### Props

Every `WaveformSoundsOptions` key except the callbacks is a runtime-declared prop, typed from the core's generated types — `sounds` / `manifest`, `player`, `search`, `filters`, `sorts`, `showCount`, `menuSearch`, `idPrefix`, `urlState`, `loopToggle`, `maxTypeChips`, `pageSize`, `columns`, `waveformStyle`, `waveformColor`, `progressColor`, `barWidth`, `barGap`, `loop`, `autoAdvance`, `arrowAudition`, `playerOptions`, `playerClass`, `strings`. Use them camelCase or kebab-case in templates (`:page-size="100"`). See [Options](/extensions/sounds/options/) for each one. `class`, `style` and `id` fall through to the host, which always carries `wfp-host`.

- **Dropdown ids**: `idPrefix`, else one from Vue's `useId()` — unique per list, identical on the server and the client.
- **`urlState`** (`boolean | string`; a bare `url-state` attribute is `true`) is runtime-only: the server renders the unfiltered list and the runtime applies the address on load.
- **A changed prop rebuilds the list** over freshly reset markup, but arrays and objects compare by value, so an equal inline literal from a re-rendering parent doesn't rebuild (and lose the visitor's filter and playback). **`loop` is the exception** — it's applied live through `setLoop()`.
- `playerOptions` callbacks always reach the latest prop value; swapping one doesn't rebuild.

Theme it through `style` — set `--ws-surface` (your page background) so the server-rendered first paint is right: `<WaveformSounds :sounds="sounds" style="--ws-surface: #09090b" />`.

### Events

The core's callbacks surface as emits, with the same arguments. `emit` is stable, so a new listener never rebuilds the list.

| Emit | Arguments |
| --- | --- |
| `@ready` | `(instance)` |
| `@play` / `@pause` / `@end` | `(sound, instance)` |
| `@filter` | `(visible: Sound[], instance)` |
| `@error` | `(error, instance)` |

The core's bubbling [`waveformsounds:*` events](/extensions/sounds/api/#events) fire from the host as well.

### Imperative API

Grab the instance with a template `ref` typed as `WaveformSoundsExpose`:

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { WaveformSounds, type WaveformSoundsExpose } from '@arraypress/waveform-vue/sounds';

const list = ref<WaveformSoundsExpose>();
</script>

<template>
  <WaveformSounds ref="list" manifest="/sounds.json" />
  <button @click="list?.setFilter({ type: 'Drum loops' })">Drum loops</button>
  <button @click="list?.setSort('bpm')">By BPM</button>
</template>
```

| Method | Signature | Notes |
| --- | --- | --- |
| `play` | `(target?, opts?: { at?: number }) => void` | By index, `id` or `Sound`; no target resumes. |
| `pause` | `() => void` | |
| `toggle` | `(target?) => void` | |
| `next` / `previous` | `() => void` | The next / previous visible sound. |
| `setFilter` | `(patch: Partial<SoundsFilter>) => void` | Merged into the current filter. |
| `clearFilters` | `() => void` | The sort stays. |
| `setSort` | `(by: SoundsSort) => void` | |
| `setLoop` | `(on: boolean) => void` | |
| `showMore` | `() => void` | |
| `instance` | `readonly WaveformSounds \| null` | The core instance (`visible`, `current`, `sounds`, `engine`, `ready`, …). |

A call before the instance exists is a no-op; a call while it's still building (a manifest fetch) runs once it's ready, in order. After that, calls are synchronous — so `play()` from a click keeps the browser's user activation.

## Server-side rendering & Nuxt

All four components are SSR / Nuxt safe by construction: the host markup (for the playlist, the `[data-track]` children; for the sound list, the whole list when given `sounds`) renders on the server, and the browser-only core is dynamically `import()`ed inside `onMounted` — which runs **only on the client**, never during server render. The interactive UI hydrates in once the library loads.

No extra guarding is needed for the imperative path: keep instantiation inside `onMounted` (the components already do), never at module top level. Reserve layout space with `style` (e.g. `:style="{ minHeight: '96px' }"`) to avoid a content shift before the waveform draws.

For Nuxt, you can render the components directly. To skip server rendering entirely and sidestep any hydration mismatch, wrap them in `<ClientOnly>`:

```vue
<template>
  <ClientOnly>
    <WaveformPlayer url="/audio/track.mp3" title="Midnight Drive" />
    <template #fallback>
      <div class="waveform-placeholder" style="min-height: 96px" />
    </template>
  </ClientOnly>
</template>

<script setup lang="ts">
import { WaveformPlayer } from '@arraypress/waveform-vue/player';
</script>
```

<Aside type="tip" title="Importing on the server is safe">
Importing a sub-path does not touch the DOM — the browser-only core is only pulled in (and constructed) client-side inside `onMounted`. If you reach for a browser-dependent core helper at request time, guard it with <code>import.meta.client</code> (Nuxt) or <code>typeof window !== 'undefined'</code>.
</Aside>
